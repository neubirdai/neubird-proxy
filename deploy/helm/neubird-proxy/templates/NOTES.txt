neubird-proxy {{ .Chart.AppVersion }}: tenant {{ .Values.tunnel.tenant }}, proxy {{ .Values.tunnel.proxy }}, relays {{ join ", " .Values.tunnel.relays }}.

The replicas turn Ready once their tunnels are up (don't use --wait the first
time if NeuBird still has to record the key).

{{- if .Values.tunnel.joinTokenEnv }}

With a join token ({{ .Values.tunnel.joinTokenEnv }} in Secret {{ .Values.env.existingSecret }}), the proxy
enrolls its own key: nothing to send NeuBird. Check:

   kubectl -n {{ .Release.Namespace }} logs -l app.kubernetes.io/instance={{ .Release.Name }} | grep -E '"(enrolled with the join token|key already enrolled|tunnel connected|tunnel connect failed)"'

Once enrolled, you may remove {{ .Values.tunnel.joinTokenEnv }} from the Secret.
{{- end }}

Without a join token: send NeuBird the key's fingerprint (not secret; the key
never leaves this cluster), and the tunnels come up once NeuBird records it:

   kubectl -n {{ .Release.Namespace }} exec deploy/{{ include "neubird-proxy.fullname" . }} -- \
     /neubird-proxy fingerprint /etc/neubird-proxy/tunnel/tunnel.key

Then, in NeuBird's UI, create each connection with the URL NeuBird gives you,
and the auth token = NEUBIRD_PROXY_TOKEN in Secret {{ .Values.env.existingSecret }}.

Revoke access at any time by changing NEUBIRD_PROXY_TOKEN, or by scaling this Deployment to 0.

{{- end }}
