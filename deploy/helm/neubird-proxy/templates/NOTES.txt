neubird-proxy {{ .Chart.AppVersion }}: inbound, Service {{ include "neubird-proxy.fullname" . }}:{{ .Values.inbound.service.port }}
({{ if .Values.inbound.tls.existingSecret }}https{{ if include "neubird-proxy.hasClientCA" . }}, client certificates required{{ end }}{{ else }}plain http: TLS must end in front of the pod{{ end }}).

Point your gateway's backend at

   {{ if .Values.inbound.tls.existingSecret }}https{{ else }}http{{ end }}://{{ include "neubird-proxy.fullname" . }}.{{ .Release.Namespace }}.svc:{{ .Values.inbound.service.port }}

and have it send the proxy token (NEUBIRD_PROXY_TOKEN in Secret {{ .Values.env.existingSecret }})
the way config.client_auth says. Check each system from inside the pod:

   kubectl -n {{ .Release.Namespace }} exec deploy/{{ include "neubird-proxy.fullname" . }} -- \
     /neubird-proxy test -config /etc/neubird-proxy/config.yaml <connection | https://host[:port]>

{{- if not .Values.networkPolicy.enabled }}

networkPolicy is off: anything in the cluster can reach port 8443. Turn it on
with networkPolicy.inboundFrom set to your gateway.
{{- end }}

{{- if .Values.inbound.tls.existingSecret }}

The proxy re-reads Secret {{ .Values.inbound.tls.existingSecret }} and the client CA every minute: renewing
them needs no restart. Expiry: neubird_proxy_tls_cert_expiry_days on :9090/metrics.
{{- end }}

Revoke access at any time by scaling this Deployment to 0, or by changing
NEUBIRD_PROXY_TOKEN and restarting it (kubectl rollout restart): pods read
the token at startup.
{{- else -}}
neubird-proxy {{ .Chart.AppVersion }}: tenant {{ .Values.tunnel.tenant }}, proxy {{ .Values.tunnel.proxy }}, relays {{ join ", " .Values.tunnel.relays }}.

The replicas turn Ready once their tunnels are up (don't use --wait the first
time if NeuBird still has to record the key).

{{- if .Values.tunnel.joinTokenEnv }}

With a join token ({{ .Values.tunnel.joinTokenEnv }} in Secret {{ .Values.env.existingSecret }}), the proxy
enrolls its own key: nothing to send NeuBird. Check:

   kubectl -n {{ .Release.Namespace }} logs -l app.kubernetes.io/instance={{ .Release.Name }} | grep -E '"(enrolled with the join token|key already enrolled|tunnel connected|tunnel connect failed)"'

Once enrolled, you may remove {{ .Values.tunnel.joinTokenEnv }} from the Secret.
{{- end }}

Without a join token: send NeuBird the key's fingerprint (not secret; the key
never leaves this cluster), and the tunnels come up once NeuBird records it:

   kubectl -n {{ .Release.Namespace }} exec deploy/{{ include "neubird-proxy.fullname" . }} -- \
     /neubird-proxy fingerprint /etc/neubird-proxy/tunnel/tunnel.key

Then, in NeuBird's UI, create each connection with the URL NeuBird gives you,
and the auth token = NEUBIRD_PROXY_TOKEN in Secret {{ .Values.env.existingSecret }}.

Revoke access at any time by scaling this Deployment to 0, or by changing
NEUBIRD_PROXY_TOKEN and restarting it (kubectl rollout restart): pods read
the token at startup.
